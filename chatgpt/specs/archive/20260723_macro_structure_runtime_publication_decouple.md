## Problem

`local/reports/macro_structure/operator/latest.html` is generated by the scheduled macro runtime, but the fixed public URL is refreshed only inside a notification cycle that has already decided to send an email.

Therefore a successful macro cycle with `notify=false` leaves the public URL behind the current local operator entry.

## Goal

Move fixed macro publication responsibility to the scheduled macro runtime and make notification email integration read-only.

```text
macro runtime:
public OHLCV -> snapshot -> history -> operator -> fixed public publication -> scenario stats -> health

notification runtime:
existing should_notify decision -> read last macro publication status -> append fixed URL block -> existing email send
```

No new notification trigger, email, LaunchAgent, schedule, host, credential, or public URL is introduced.

## Runtime publication contract

1. Reuse `src.notification.macro_structure_public_delivery.publish_macro_structure_public` and its existing source validation, transport validation, temporary upload, and atomic remote rename.
2. Run publication exactly once after all core steps succeed and the operator has produced a fixed entry.
3. Core success remains only `snapshot + history + operator`.
4. Publication failure or disabled state must not change a successful core result or process exit code.
5. Publication failure must not suppress scenario stats or health generation.
6. If core fails, publication is `not_run` with stable reason `macro_public_core_pipeline_failed`.
7. Persist one bounded `public_delivery_generation` object in the atomic macro runtime status.
8. Allowed fields:
   - `attempted`
   - `status`: `published`, `failed`, `disabled`, or `not_run`
   - `public_url` only when published
   - `entry_status`
   - `entry_id`
   - `source_sha256`
   - `cutoff_jst`
   - `stale_status`
   - `continuity_status`
   - `data_quality_status`
   - stable `error_code`
9. Do not persist SSH host, key path, remote path, stdout, stderr, exception text, secret values, or raw HTML.
10. Config loading or publisher exceptions are converted to stable bounded failure metadata; they do not escape and do not change core success.
11. Dry-run must not load secrets, read `.env`, run SSH/rsync, or write status. It only exposes that publication follows core success and identifies the relative fixed-entry source.

## Notification contract

1. Remove the notification-cycle call that republishes the macro page.
2. Add a bounded reader that loads `logs/runtime/macro_structure_service_last_result.json` and converts `public_delivery_generation` into the existing flat delivery result accepted by `format_macro_structure_email_block`.
3. The reader is called only when the existing notification logic has already selected `notify=true`.
4. The notification process performs no SSH, rsync, remote rename, or local fixed-entry validation for macro publication.
5. Preserve existing email subject, recipient, send count, cooldown, notification kind, pending-email behavior, detail-page behavior, and duplicate suppression.
6. A missing or invalid macro runtime publication record yields one stable unavailable status line; it does not suppress an otherwise-approved email.
7. `notify=false` performs neither email send nor macro publication/status read.

## Health scope

Do not change the health-state algorithm in this task.

Existing health generation remains once per macro cycle after atomic runtime status publication. The new publication object is observable in runtime status; broader public-URL health policy is deferred unless a material defect remains after this correction.
