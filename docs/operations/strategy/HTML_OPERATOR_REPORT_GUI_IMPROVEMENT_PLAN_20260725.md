> [!abstract]
> 現行のHTML報告書は、必要な分析情報を広く表示できている一方、同じ結論の重複、時間軸の混在、Long・Shortの視点切替、内部変数に近い表現、固定説明と最新情報の視覚的競合によって、人間が「今どう見るべきか」を短時間で把握しにくい。本計画では、既存の判定・スコア・gate・価格計算を変更せず、表示専用の情報設計、用語、見出し、優先順位、レイアウトを整理する。

## 🎯 目的と対象

### 目的

notification mailからHTML報告書を開いた人間が、最初の数秒で次の5点を理解できる状態を作る。

1. 今は新規エントリー可能か、見送りか
2. 4時間足・1時間足・15分足は、それぞれどちらを向いているか
3. LongとShortのどちらを、どの条件で監視するか
4. 重要な価格帯、無効化ライン、利確目安はどこか
5. 何が起きたら現在の判断が変わるか

### 対象

主対象は、次の生成物と生成経路である。

- 確認対象HTML: `logs/notifications_html/manual-trading/main/20260724_220500.html`
- 主生成コード: `src/notification/detail_page.py`
- 15分足の実行分類: `src/analysis/side_aware_mtf_action.py`
- 最終的な競合・停止判定: `src/analysis/operator_decision.py`
- 候補成熟度の分類: `src/feedback/manual_operator_shadow_surface.py`
- 4H・1Hの構造優先度: `src/analysis/structural_priority.py`
- 大転換候補: `src/analysis/big_chance.py`

### この計画の性格

本計画は**表示専用の改善計画**である。

- 既存の分析値を別の意味へ変更しない
- Long・Shortのスコア計算を変更しない
- 4H・1H・15Mの判定ロジックを変更しない
- gate、threshold、classifier、通知条件を変更しない
- 自動注文や正式GOを追加しない

## 🔎 確認済みの現行構造

現行HTMLは、概ね次の順序で生成されている。

```text
総合ヒーロー
→ 現在発火中の警戒
→ 現在の行動方針
→ 現在の売買判断
→ 4H / 1H構造優先度
→ チャートとLong・Short価格計画
→ 判断が変わる条件
→ 大転換候補と市場環境
→ 詳細・内部情報
```

| 現行エリア | 主なデータ | 本来の役割 | 現在の混乱要因 |
|---|---|---|---|
| 総合ヒーロー | `operator_decision`、通知context、3つのconfidence shadow | 今の総合結論 | WAIT、見送り、監視、条件待ちが同時に並ぶ |
| 現在の行動方針 | `side_aware_mtf_action` | 優先側と15分足の次行動 | 後続の売買判断と意味が重なる |
| 現在の売買判断 | manual operator shadow surface | 候補の成熟段階 | A・B・C・STOPと日本語説明が二重化する |
| 構造・チャート | `structural_priority`、Long・Short setup、SVG | 中期方向と具体的価格 | 異なる種類のスコアが同じ見た目で並ぶ |
| 条件・大転換候補 | 価格条件、`big_chance_candidate`、市場環境 | 次の変化と補助監視 | 補助候補が通常判断と同じ強さで見える |

### 現在の主要問題

1. **同じ結論が複数回表示される**
   - `WAIT`
   - `新規見送り`
   - `条件待ち`
   - `判定材料不足`
   - `価格帯を監視`

2. **「方向」を表す値が複数ある**
   - ヒーローの方向評価
   - Long・Shortの独立方向スコア
   - 4H・1H構造配分
   - 15分足の実行優先側
   - 大転換候補の方向

3. **時間軸が見出しに含まれない表現がある**
   - 「ロング優先」だけでは、4H・1H・15Mのどの話か分からない
   - 中期はShort、15分足はLongという正常な非対称状態が、単に「競合」とだけ表示される

4. **内部コードに近い表現が人間向け表示へ残る**
   - `A_FORMAL`
   - `B_CHECK_15M`
   - `countertrend`
   - `stale`
   - `PRIMARY`
   - `ENTRY LAYERS`

5. **固定説明が最新情報と同程度の面積を使う**
   - report-only説明
   - A・B・C・STOPの定義
   - 毎回同じ注意書き
   - 操作説明

6. **最新の動的情報が埋もれる**
   - 現在価格
   - 更新時刻
   - 4H・1H・15Mの関係
   - 次に確認する価格イベント
   - 現在の優先側が変わった理由

## 🧭 改善の基本原則

### 1. 一つの意味には一つの標準表現を使う

総合結論、時間軸、候補成熟度、価格条件を別の概念として分離する。同じ状態を複数の言い回しで繰り返さない。

### 2. 上位時間足から実行時間足へ読む

表示順を次へ統一する。

```text
4時間足の大局
→ 1時間足の確認
→ 15分足の実行状態
→ Long・Shortの具体的価格
```

### 3. 最新情報を大きく、固定説明を小さくする

- 最新の結論、価格、時間軸、条件は大きく表示する
- 毎回同じ説明は小さくするか、折りたたむ
- 内部コードは通常画面へ出さず、詳細欄だけに残す

### 4. 「スコア」と「確率」を明確に分ける

現在の数値は勝率や確率ではない。表示名に「内部評価」「構造配分」「独立評価」を明示し、誤読を防ぐ。

### 5. 色だけで意味を伝えない

Longは緑、Shortは赤、待機は黄、補助情報は青・灰を基本とするが、必ず日本語ラベルを併記する。

### 6. 表示改善のために分析ロジックを変更しない

UIは既存データを正確に翻訳する。UI都合でgate、score、threshold、classifierを変更しない。

## 🗂️ 新しい5エリア構成

### エリア1：今の結論

#### 答える質問

> 今は入るのか、待つのか。なぜか。

#### 主表示

- `新規エントリー見送り`、`15分足の最終確認待ち`などの日本語結論
- 小さな補助バッジとして`WAIT`
- 現在価格
- 更新時刻と有効期限
- 結論を決めた最重要理由を1文
- 最重要警戒を最大2件
- report-only安全表示を1行

#### 3つの内部評価値

現行の`方向 / 実行 / 待機`は、次の日本語へ変更する。

| 現行 | 改善後 | 表示例 |
|---|---|---|
| 方向 | 方向の強さ | 強い `80` |
| 実行 | 実行準備度 | 低い `28` |
| 待機 | 待機圧力 | 中程度 `51` |

数値を主役にせず、**状態語を先、数値を後**にする。

```text
方向の強さ：強い（80）
実行準備度：低い（28）
待機圧力：中程度（51）
```

#### このエリアから外すもの

- 成行・指値・ブレイク・逆方向短期の4セル
- Long・Short双方の詳細条件
- A・B・C・STOPの定義
- 価格レイヤーの詳細

これらは後続エリアへ移す。

### エリア2：時間軸別の方向

#### 答える質問

> 4時間足、1時間足、15分足は、それぞれどちらを向いているか。互いに一致しているか。

#### 表示形式

4H → 1H → 15Mの順に、同じ高さの3カードまたは1本のタイムラインで表示する。

| 時間軸 | 役割 | 表示内容 |
|---|---|---|
| 4時間足 | 中期構造 | Long・Shortの構造配分と優勢側 |
| 1時間足 | 戦術的な確認 | 反転、継続、様子見の状態 |
| 15分足 | 実行確認 | 現在の優先側、候補状態、追いかけ可否 |

#### 必須の総括文

時間軸の関係を、人間向けの1文へ変換する。

例：

```text
中期はショート優勢ですが、15分足ではロングの反発を確認中です。
逆方向候補のため、新規エントリーは見送ります。
```

#### 整合状態の日本語

| 内部状態 | 日本語表示 |
|---|---|
| `aligned` | 中期と15分足が一致 |
| `countertrend` | 15分足は中期方向に逆行 |
| `turning_candidate` | 反対方向への転換候補 |
| `neutral` | 時間軸の方向は未確定 |
| direction conflict | 方向競合のため新規見送り |

#### 構造スコアの表示名

`Long 32 / Short 68`は方向候補の独立スコアではなく、合計100の中期構造配分である。

表示名を次へ統一する。

```text
中期構造の配分
Long 32 / Short 68
```

`32% / 68%`と表示する場合も、確率ではなく構造配分である旨を短く明示する。

### エリア3：15分足の実行判断

#### 答える質問

> LongとShortのどちらを、何が起きたら検討できるか。

#### 統合対象

現行の次の2エリアを統合する。

- 現在の行動方針
- 現在の売買判断

両者は内部データの目的が異なるが、人間から見ると「Long・Shortの現在状態と次条件」を重複表示している。

#### Long・Shortカードの標準構成

各カードは同じ項目順にする。

1. 側: ロング / ショート
2. 現在の状態
3. 時間軸との関係
4. 次に確認する条件
5. エントリー候補帯
6. 無効化ライン
7. 利確目安1・2
8. 今すぐ入らない理由

#### 表示例

```text
ロング｜15分足の確認待ち
中期構造には逆行

次の確認：64,073–64,137で反発を維持
無効化：63,910
利確目安：64,358 / 64,572

現在は方向競合のため、新規エントリー見送り
```

#### A・B・C・STOPの扱い

通常画面では日本語を主表示する。

- A: 最終確認候補
- B: 15分足の確認待ち
- C: 価格帯を監視
- STOP: 新規停止・保護確認

内部分類記号は小さな補助表示または詳細欄へ移す。

```text
15分足の確認待ち
内部分類：B
```

#### 優先側の見せ方

`PRIMARY`ではなく、次の日本語を使う。

```text
現在の優先側
```

優先側ではないカードも消さない。Long・Shortの非対称性を比較できるようにし、優先側だけ枠線と見出しを強調する。

### エリア4：価格マップ

#### 答える質問

> 現在価格は、Long・Shortの候補帯、無効化、利確目安に対してどこにいるか。

#### 表示優先順位

1. 15分足チャート
2. 現在価格
3. Long・Shortの浅い候補帯
4. Long・Shortの本命ゾーン
5. 無効化・回収・継続ライン
6. SL・TP
7. 1H・4Hの補助表示

#### チャートの見出し

現行の「チャートと価格レイヤー」から、次へ変更する。

```text
価格マップ｜15分足の実行位置
```

時間足切替時は見出しも連動させる。

- `価格マップ｜15分足の実行位置`
- `価格マップ｜1時間足の確認`
- `価格マップ｜4時間足の大局`

#### 価格情報の重複ルール

- 完全な価格一覧はこのエリアを正本とする
- エリア3には、直近のエントリー候補帯と無効化だけを要約表示する
- SL・TPの詳細値は、左右カードとチャートで同じ値を使う
- 同一値を異なる名称で表示しない

#### スコア名の区別

Long `38`、Short `85`は独立した方向材料スコアであり、合計100ではない。

表示名を次へ変更する。

```text
方向材料スコア（独立評価）
```

補足として次を明記する。

```text
勝率・確率・実行許可ではありません
```

### エリア5：判断が変わる条件・補助監視

#### 答える質問

> 次に何が起きたら、現在の判断を更新するか。

#### 主表示

「判断が変わる条件」を最上位に置き、Long・Short・共通条件をイベント形式で表示する。

例：

- ロング起動: 回収後に継続ラインを維持
- ロング弱化: 無効化帯を割り、回収できない
- ショート再評価: 本命ゾーンで上値拒否
- 共通見送り: 重要価格帯付近のノイズが継続

#### 大転換候補の扱い

Big Chanceは通常判断を上書きしない補助候補であるため、視覚的な優先度を下げる。

見出しを次へ変更する。

```text
補助監視｜反対方向への大転換候補
```

状態別表示：

| 状態 | 表示 |
|---|---|
| 現在方向と一致 | 補助候補として通常表示 |
| 現在方向と不一致 | 現在の優先判断とは不一致 |
| 失効 | 候補失効・再評価済み |
| データ不足 | 判定材料不足 |

`stale`という語は通常画面へ出さない。

#### 市場環境の扱い

Funding、ATR Ratio、Volume Ratioは結論ではなく補足情報なので、コンパクトな1行または折りたたみ欄へ移す。

- 資金調達率
- 値動きの大きさ（ATR比）
- 出来高比

## ⏱️ 時間軸とLong・Shortの見せ方

### 見出しには必ず時間軸を含める

避ける表現：

```text
ロング優先
ショート優勢
方向競合
```

改善後：

```text
4時間足中心：中期はショート優勢
1時間足：方向確認中
15分足：ロングの反発確認待ち
4HはShort、15MはLongのため方向競合
```

### 時間軸別の役割を固定する

| 時間軸 | 画面上の名称 | 判断上の役割 |
|---|---|---|
| 4H | 中期構造 | 大局の優先方向 |
| 1H | 確認時間足 | 継続・反転・転換の確認 |
| 15M | 実行時間足 | エントリー可否の最終確認 |

### Long・Shortの変化を正常な状態として表示する

時間軸によってLong・Shortの見方が変わること自体は異常ではない。次のように分類して表示する。

1. **一致**
   - 4H、1H、15Mが同方向
   - 「時間軸が一致」と表示

2. **逆行候補**
   - 中期方向と15M候補が反対
   - 「中期構造に逆行。短期反発候補」と表示

3. **転換候補**
   - 中期と反対方向へconfirmedな転換兆候がある
   - 「反対方向への転換候補」と表示

4. **方向競合**
   - スコア、15M、market mapなどが同時に矛盾し、`operator_decision`がblocked
   - 「4HはShort、15MはLong。判断材料が競合しているため新規見送り」と具体化

5. **判定材料不足**
   - 方向を無理に補完しない
   - 「方向未確定」と表示

### 表示上の重要ルール

> [!warning]
> 「Long優先」「Short優先」という見出しは、必ず対象時間軸を併記する。時間軸を省略した総合方向は作らない。

## 🈶 用語統一と日本語化

### 主要状態

| 現行表現 | 通常画面の標準表現 | 備考 |
|---|---|---|
| `WAIT` | 新規エントリー見送り | WAITは小さな補助バッジのみ |
| `A_FORMAL` | 最終確認候補 | 正式GOではない |
| `B_CHECK_15M` | 15分足の確認待ち | 人間がタイミング確認 |
| `C_WATCH_ZONE` | 価格帯を監視 | 実行条件未成立 |
| `STOP_OR_EXIT` | 新規停止・保護確認 | 新規見送り、既存保護を優先 |
| `armed` | 条件接近 | 次条件を監視中 |
| `watch` | 監視中 | 未起動 |
| `follow_through` | 継続確認 | 条件成立後の維持確認 |
| `late` | 追いかけ禁止 | 遅延候補 |
| `invalidated` | 候補失効 | 再利用しない |
| `dormant` | 未起動 | 現在は対象外 |
| `aligned` | 時間軸が一致 | 構造と実行方向が一致 |
| `countertrend` | 中期方向に逆行 | 短期反発・逆張り候補 |
| `turning_candidate` | 転換候補 | confirmedな反対方向兆候 |
| `neutral` | 方向未確定 | 中立または材料不足 |
| `insufficient_evidence` | 判定材料不足 | 推測で補完しない |
| `stale` | 現在の優先判断とは不一致 | 補助候補に使用 |
| `PRIMARY` | 現在の優先側 | 日本語を主表示 |

### セクション・項目名

| 現行表現 | 改善後 |
|---|---|
| `REPORT ONLY / HUMAN DECISION` | 参考情報・最終判断は人間 |
| `BTC CURRENT PRICE` | 現在価格 |
| `4H / 1H STRUCTURAL PRIORITY` | 中期構造（4時間足中心） |
| `ENTRY LAYERS` | エントリー候補帯 |
| `VALIDATION` | 成立・無効化条件 |
| `RISK / TARGET` | 損切り・利確目安 |
| `FUNDING` | 資金調達率 |
| `ATR RATIO` | 値動きの大きさ（ATR比） |
| `VOLUME RATIO` | 出来高比 |
| `B / 未記録` | グレードB・状態未記録 |

### 内部変数の表示ルール

- 通常画面では日本語だけを表示する
- 内部コードは「内部判定値」の折りたたみ欄だけに残す
- `none`、`unknown`、`wait`などをそのまま出さない
- 未取得と該当なしを区別する
  - 未取得: `データ未取得`
  - 証拠不足: `判定材料不足`
  - 該当なし: `該当なし`
  - 待機: `確認待ち`

## 🔠 固定説明と最新情報の表示優先度

### 表示レベル

| レベル | 内容 | 視覚優先度 |
|---|---|---|
| L1 | 現在の結論、価格、更新時刻、方向競合 | 最大 |
| L2 | 時間軸、次条件、エントリー帯、無効化 | 大 |
| L3 | スコア、Big Chance、市場環境 | 中〜小 |
| L4 | 用語説明、安全説明、内部値、Runtime | 折りたたみまたは最小 |

### 固定説明の扱い

毎回同じ説明は、本文の大きなカードにしない。

- report-only説明は上部に1回
- A・B・C・STOPの定義はヘルプまたはdetails
- チャート操作説明はボタン付近の短いラベル
- 安全境界の全文はフッターまたはdetails
- 「最終判断は人間」という文を複数セクションで繰り返さない

### 最新情報の扱い

次は常に折りたたまず表示する。

- 現在価格
- 最終更新時刻
- 総合結論
- 4H・1H・15Mの方向
- 現在の優先側
- 次に確認する条件
- 無効化ライン

## 🧹 情報重複の整理方針

### 一つの情報に一つの正本表示場所を決める

| 情報 | 正本表示場所 | 他エリアでの扱い |
|---|---|---|
| 総合結論 | エリア1 | 繰り返さない |
| 時間軸の方向 | エリア2 | エリア3では「一致・逆行」だけ要約 |
| 候補成熟度 | エリア3 | A/B/C/STOPの説明はdetails |
| 完全な価格一覧 | エリア4 | エリア3は直近帯と無効化のみ |
| 判断変更イベント | エリア5 | 他エリアへ重複表示しない |
| Big Chance | エリア5 | ヒーローへ出さない |
| 安全境界 | 上部1行＋フッター | 各カードで繰り返さない |

### 現行の重複を具体的に整理する

1. ヒーローの4実行方法セルはエリア3へ移す
2. 「現在の行動方針」と「現在の売買判断」を統合する
3. A・B・C・STOPの固定定義を折りたたむ
4. Entry・SL・TPの完全一覧は価格マップを正本にする
5. 同じ待機理由は、ヒーローでは上位1件、詳細では全件にする
6. Big Chanceの方向が通常判断と異なる場合、見出しで明確に補助候補と示す

## 🎨 視覚デザインとレスポンシブ方針

### 文字の階層

- 総合結論: 最も大きい
- 現在価格: 総合結論と同等か一段小さい
- セクションの動的見出し: 大きい
- 固定セクション名: 小さなkicker
- 説明文: 小さく、低コントラスト
- 内部コード: details内のみ等幅フォント

### 見出しの構成

固定名と最新状態を分ける。

```text
時間軸別の方向
中期はShort、15分足はLongのため新規見送り
```

上段の固定名は小さく、下段の最新状態を大きくする。

### 色の意味

| 色 | 意味 |
|---|---|
| 緑 | Long側の情報 |
| 赤 | Short側の情報 |
| 黄 | 待機、注意、追いかけ禁止 |
| 青 | 中立、構造説明、補助情報 |
| 灰 | 失効、未取得、固定説明 |

> [!note]
> 緑や赤だけでLong・Shortを区別せず、必ず文字ラベルを併記する。

### 余白と密度

- 1カードに複数の説明段落を入れない
- 重要値は1行1意味にする
- セクション間の余白を、カード内の余白より大きくする
- 同じ背景色のカードを連続させず、役割ごとにグループ化する

### デスクトップ

```text
エリア1：総合結論 + 現在価格
エリア2：4H / 1H / 15Mを横並び
エリア3：Long / Shortを2列比較
エリア4：チャートを主、価格一覧を補助
エリア5：判断変更条件を主、補助監視を右側
```

### モバイル

```text
総合結論
→ 現在価格・更新時刻
→ 4H
→ 1H
→ 15M
→ 優先側カード
→ 反対側カード
→ チャート
→ 判断変更条件
→ 補助監視
→ details
```

横スクロールが必要な情報はチャートだけに限定する。

## 📌 結論

現行HTMLの問題は、情報不足ではなく、**異なる意味の情報が同じ強さで並び、同じ意味が異なる言葉で繰り返されていること**である。

改善の中心は次の5点とする。

| 改善軸 | 結論 |
|---|---|
| 情報順序 | 結論 → 時間軸 → 15分足実行 → 価格 → 判断変更条件 |
| 時間軸 | 4H・1H・15Mを一つのエリアで比較 |
| Long・Short | 必ず対象時間軸と一致・逆行状態を併記 |
| 用語 | 日本語を主表示し、内部コードはdetailsへ移動 |
| 視覚優先度 | 最新情報を大きく、固定説明と補助候補を小さくする |

最初に実装すべきなのは、色や装飾の変更ではない。**用語の正本化、時間軸の明示、重複する2つの判断エリアの統合、最新情報と固定説明の優先度分離**である。これらを完了した後に、余白、色、モバイル表示を整える。
